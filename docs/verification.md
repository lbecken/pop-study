# Verification

What has been checked, how to repeat it, and what has not been checked.
All results below were recorded against original commit `25243550`.

## Commands

Python tools (unit tests; add `POP_SOURCE_DIR` for the original-data tests):

```bash
POP_SOURCE_DIR=../pop-original python3 -m pytest tests -q
```

C port:

```bash
cmake -S modern-port -B build/port -DPOP_SOURCE_DIR=../pop-original -DPOP_WERROR=ON -DPOP_SANITIZE=ON
```

```bash
cmake --build build/port
```

```bash
ctest --test-dir build/port --output-on-failure
```

The two comparisons with the original code, at any size and seed (data
directory as generated by the CMake build):

```bash
python3 modern-port/tests/fuzz_control.py build/port/pop_worldrun build/port/data ../pop-original 1000 42
```

```bash
python3 modern-port/tests/trace_kidstep.py build/port/pop_worldrun build/port/data ../pop-original 500 42
```

Whether the first of those would notice a wrong port (takes minutes):

```bash
python3 modern-port/tests/mutation_check.py build/port/data ../pop-original
```

Extraction with its own consistency report:

```bash
python3 tools/extract_assets/extract_animdata.py --source ../pop-original --out build/data
```

## Kinds of evidence

| Kind | Used for | Strength |
| --- | --- | --- |
| Parse consistency | image tables (sizes add up in all 16 files) | strong for the container format |
| Layout fit | assembled `FRAMEDEF.S`, `SEQTABLE.S`, `TABLES.S`, `HRTABLES.S` end below the next module's origin; internal symbols land where `dum` sections say | strong for the assembler subset |
| Closed-form match | blitter tables regenerated by formula equal the assembled originals byte for byte | strong |
| Structural checks | sequence table: every label, entry and branch target on an instruction boundary | strong |
| Internal symmetry | right-facing run is the exact dot mirror of the left-facing run | strong for the position and mirror code together |
| Physical plausibility | supporting foot stays within 2 units for each stance; feet meet the floor line | moderate |
| Two implementations | C interpreter vs Python decoder, 45,600 ticks identical; C effect renderer vs Python, 26,204 samples | catches slips, not a shared misreading |
| Executing the original | sound effects obtained by running the assembled `SOUND.S` in a 6502 simulator; timing equals the hand-derived loop formula | strong for behaviour; depends on the simulator's cycle table |
| Differential fuzzing | each ported C routine against the original routine in the simulator, on random states wider than valid ones (`docs/oracle.md`) | strong: independent of my reading of the code; depends on the assembler and simulator being right |
| Mutation check | 104 deliberately wrong builds of the control, collision and moving-object code, each run against the comparison (`modern-port/tests/mutation_check.py`) | shows the comparison has teeth, and where its inputs were thin: the first version missed six boundary values, since added |
| Multi-frame trace | the ported per-frame steps run for 60 frames with state carried over, C against the original after each call | strong for how the routines work together; says nothing about the steps not yet ported |
| Coverage | gcov on the C under the fuzz inputs | shows which branches the comparison reached at all |
| Cross-screen continuity | rendered screens placed by the level map line up at their edges | moderate: wrong piece offsets or neighbour rules would show as seams |
| Visual inspection | contact sheets, run-cycle sheets, rendered rooms | weak, by eye |

## A weakness the mutation check found in the comparison

Cases in which the port reports "unmodelled" (the original would read or
write outside the tables the port has) are skipped, not compared. One
injected error made the port compute a redraw-buffer index of 30 where the
original computes none; the port's bounds check then reported "unmodelled"
and the case was skipped, hiding the error. The remedy was to remove the
reason for skipping: the redraw buffers are now one contiguous array, as in
the original's memory, so index 30 of one buffer is byte 0 of the next and
the stray write is compared like any other. The same idea (model the memory,
not the intent) already applied to the collision buffers. Skipped cases
remain for reads beyond tables whose neighbours are not modelled; they are
counted in every run (well under 1 % outside the collision group, where
random frames without images account for about 7 %).

## Not verified

- **Nothing has been compared with the running game.** The repository has no
  disk image and no assembled binary. Every result above is consistency with
  the source and with itself.
- The project's assembler and 6502 simulator have not been compared with
  independent ones (unknowns P1, P5).
- No audio has been compared with a real machine or an emulator.
- Real frame timing (unknown T1).
- macOS and Windows builds of the port.
- Anything involving collision, moving level objects, opponents' decisions,
  input devices or drawing: not ported, so not compared.
- Which opponent image set each level uses (unknown G9), which the port will
  need for opponents' collision sizes.
